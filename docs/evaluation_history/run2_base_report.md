# run2_base: результаты сборщиков и как они посчитаны

Ветки симуляции: мышь `…random_cut_amp_ec1x3_in5ng_rb3x_ss250` (6 образцов ERR346596–601, только IGH),
человек `…random_cut_amp_umicons_in5ng_rb3x_ss250` (один объединённый образец, IGH/IGK/IGL).
Протокол симуляции: ПЦР1 → порция 5 нг → один случайный разрез → отбор по размеру 250±40 → ПЦР2 → NovaSeq PE150.
Сборщики: TRUST4, rnaSPAdes, Trinity. Оценка: `benchmark_assemblers_{mouse,human}.ipynb`, схема
`unique_vj_trim20` (мышь) / `unique_vj_trim0` (человек). Числа — из `full_runs_*.tsv` в этой папке.

Везде ниже: **число (доля)**; доля = число / знаменатель, знаменатель указан у таблицы.

## 0. Откуда метрики

**Метрики спроектированы нами** и считаются сравнением выхода сборщика с эталоном симуляции: известно, какие
молекулы были в пробирке. Сами сборщики правильность не оценивают. Из их выходов берётся только **поддержка
контига** (раздел 5): у TRUST4 — `consensus_count`, у rnaSPAdes — `cov` из имени контига. Классы и пороги
(вся V…J, ≥95% длины, ≥98% идентичности) выбраны по аналогии с оценкой транскриптомных сборок
(rnaQUAST считает «95%-assembled» транскрипты).

**Отличия считаются только внутри эталонной V…J.** Части контига за её пределами (лидер, праймер, C-область,
хвосты праймеров) не оцениваются: эталоном для них служит только V…J.

### Эталон
- Для шаблона симуляции берётся V…J: `template[vj_start + TRIM5 : vj_end]`; `TRIM5` = 20 нт у мыши (зона
  FR1-праймера, её задаёт праймер, а не молекула), 0 у человека (праймер в лидере, вне V…J).
- Шаблоны с одинаковыми (локус, V…J) объединяются в одну **уникальную V…J**.
- **Проверенная** V…J: у человека подтверждена консенсусом UMI, у мыши — ≥2 рида исходных данных после
  схлопывания ошибок. Непроверенные могут нести ошибку исходного секвенирования; основные метрики — по проверенным.
- **Копии** — сколько раз V…J встречалась в исходных данных (человек — число UMI, мышь — риды после схлопывания);
  группы 1 / 2–4 / 5+. У мыши группы «1» нет: такие V…J не проверены по определению.
- Знаменатели (сумма по образцам): мышь **33 979** проверенных уникальных V…J (+1 022 927 непроверенных);
  человек **48 100** (IGH 28 794, IGK 12 499, IGL 6 807; +69 889 непроверенных).

### Формулы

Обозначения для одного образца:

| символ | что это |
|---|---|
| `T` | проверенные уникальные V…J образца; `v(t)` — последовательность V…J шаблона `t` |
| `T*` | все уникальные V…J образца (проверенные и непроверенные) |
| `C` | контиги сборщика; `rc(c)` — обратный комплемент контига `c` |
| `v ⊑ c` | `v` целиком входит в `c` или в `rc(c)` подстрокой (поиск по первому 31-меру `v` и проверка всего вхождения) |
| `h(t)` | лучшее выравнивание `v(t)` на контиги (`minimap2 -c -x sr -N 50 -p 0.5`; ключ — совпадения − NM, затем длина) |
| `qs, qe, ℓ` | начало и конец выравнивания в `v(t)`, длина `v(t)` |
| `NM`, `M`, `L` | число замен и инделей, число совпавших оснований и длина блока выравнивания |
| `e_clip` | число несовпадений в концах `v(t)`, обрезанных выравниванием, при сравнении с основаниями контига напротив них (если контиг их перекрывает) |
| `g(c)` | лучшее выравнивание контига `c` на эталонные V…J; `ts, te, ℓ_t` — его координаты в эталоне и длина эталона |
| `s(c)` | поддержка контига (раздел 5) |

Классы полноты шаблона `t` (проверяются по порядку):

| класс | условие |
|---|---|
| `exact_full` | `∃ c ∈ C : v(t) ⊑ c` |
| `one_diff_full` | `NM + e_clip = 1`, контиг перекрывает всю `v(t)` |
| `near_full` | `(qe − qs) / ℓ ≥ 0,95` и `M / L ≥ 0,98` |
| `partial` | выравнивание есть, но условия выше не выполнены |
| `missing` | выравнивания нет |

`доля класса k = |{t ∈ T : класс(t) = k}| / |T|` (числитель и знаменатель суммируются по образцам).

Классы точности контига `c`:

| класс | условие |
|---|---|
| `exact_full` | `∃ t ∈ T : v(t) ⊑ c` |
| `unverified_match` | `c` содержит только непроверенные V…J, либо `g(c)` ведёт к непроверенной V…J при классе near_full / correct_partial |
| `near_full` | `(te − ts) / ℓ_t ≥ 0,95` и `M / L ≥ 0,98` |
| `correct_partial` | `M / L ≥ 0,98` и `L ≥ 100` |
| `incorrect` | выравнивание хуже |
| `unmapped` | выравнивания нет |

`доля класса k = |{c ∈ C : класс(c) = k}| / |C|`.

Структура контига `c`. `H(c)` — все выравнивания контига на `T*`, `D(h)` — позиции отличий выравнивания `h` в
координатах контига, `G = {h ∈ H(c) : M/L ≥ 0,98}`, `b` — лучшее из `G` (совпадения − NM, затем длина):

| класс | условие (первое выполненное) |
|---|---|
| `exact_verified` / `exact_unverified` | `∃ t ∈ T* : v(t) ⊑ c`; среди таких `t` есть проверенная / только непроверенные |
| `chimera` | `|c| ≥ 200`, первые и последние 60% `c` целиком и без отличий совпадают с **разными** эталонами |
| `other` | `G` пусто |
| `exact_fragment` | `D(b) = ∅`: отличий нет, но целой эталонной V…J в контиге нет |
| `mosaic` | для каждой `p ∈ D(b)` есть `h ∈ G`, `h ≠ b`, к проверенному эталону, покрывающее `p`, и `p ∉ D(h)` |
| `unverified_variant` | то же, если допускаются непроверенные эталоны |
| `novel_error` | хотя бы одно отличие `b` не объясняется ни одним эталоном |
| `unmapped` | выравниваний нет |

```
эталон A   ....G.........................C....      (родственники A и B отличаются в 2 позициях)
эталон B   ....T.........................A....
контиг     ....G.........................A....  → mosaic         (G от A, A от B)
контиг     ....G.............T...........C....  → novel_error    (T нет ни у A, ни у B)
контиг           ....................             → exact_fragment (кусок A без отличий, A не целиком)
контиг     [   = A (60%)   ][  = B (60%)   ]      → chimera        (5′ и 3′ точно от разных V…J)
```

CDR3: клонотип `k = (образец, локус, junction)` по проверенным V…J; `найден(k) = 1`, если `junction ⊑ c` для
какого-либо контига образца; `доля = Σ найден(k) / |K|`. Контроль — клонотипы, у которых все шаблоны в классе
восстановимости `no_reads`.

Пороги поддержки: `осталось(τ) = |{c ∈ C : s(c) ≥ τ}|`;
`exact recall(τ) = |{t ∈ T : ∃ c ∈ C, v(t) ⊑ c, s(c) ≥ τ}| / |T|`.

Восстановимость шаблона считается в симуляции по фрагментам, получившим риды, на интервале V…J, `K = 31` нт:
стык соседних позиций покрыт ридом, если рид заходит на ≥31 нт по обе стороны, покрыт фрагментом — то же для
фрагмента. `no_reads` — ни одного рида в V…J; `partial_read_coverage` — есть непрочитанные позиции;
`full_coverage_unlinked` — есть стык, не покрытый ни одним фрагментом; `full_coverage_mate_linked_only` — все стыки
покрыты фрагментами, но не все ридами; `full_coverage_read_overlap` — все стыки покрыты ридами.

## 6. Сборщики: для чего созданы, стадии, выходы

### TRUST4

- Репозиторий и документация (README): https://github.com/liulab-dfci/TRUST4
- Статья: Song L. et al. *TRUST4: immune repertoire reconstruction from bulk and single-cell RNA-seq data.*
  Nature Methods 18, 627–630 (2021). doi:10.1038/s41592-021-01142-2
- **Для чего:** найти TCR/BCR (прежде всего CDR3 и клонотипы с их частотой) в обычном bulk RNA-seq, где
  иммунные риды — малая доля, и в single-cell 5′ (10x). Есть режим `--repseq` для таргетного AIRR-seq.
- **Где эффективен:** обнаружение клонотипов и CDR3, оценка их частот, аннотация V/D/J/C; полноразмерные цепи
  при хорошем покрытии. Задача «развести тысячи вариантов V…J, отличающихся 1–7 SHM, без UMI» — не его профиль.

Наш запуск: `run-trust4 -f mouse_IMGT+C.fa --ref mouse_IMGT+C.fa -1 R1 -2 R2 -t 20 --noExtraction
--outputReadAssignment --clean 0`.

**Стадия 0. Референс.** `BuildImgtAnnot.pl` собирает из IMGT последовательности V, D, J и C генов
(`mouse_IMGT+C.fa`, `human_IMGT+C.fa`).

**Стадия 1. Отбор кандидатов** (`fastq-extractor`): по k-мерам референса оставляет риды, похожие на
V/J/C. **У нас пропущена** (`--noExtraction`): в ампликонной библиотеке все риды — BCR.

**Стадия 2. Жадная сборка** (`trust4`, однопоточная). Риды обрабатываются по одному (после внутренней
сортировки); перекрывающиеся мейты сливаются. Для рида по k-мерному индексу ищутся сборки-кандидаты, рид
выравнивается на их консенсус. Если сходство ≥ порога (90%; 95% и 97% для сборок, где уже ≥2 и ≥20 ридов),
рид добавляется: в каждой позиции сборки обновляются счётчики A/C/G/T, консенсус = самый частый нуклеотид.
Иначе рид начинает новую сборку.

```
сборка #1 (консенсус)  GAGGTTCAGCTG...TGTGCTAGATATTAC...TGG
счётчики позиции 50     A:0 C:0 G:812 T:41      ← 41 рид родственника с T сливается в ту же сборку
новый рид                     CAGCTG...TGTGCTAGAT          сходство 99% ≥ 90% → добавлен в #1
рид другого клона             CAGCAA...TGTGCGAGAC          сходство 82% < 90% → новая сборка #2
```

Затем в логе: `Try to rescue … reads` — повторная попытка для неприсоединённых ридов;
`Extend assemblies by mate pair information` — удлинение/склейка сборок, если R1 в одной, а R2 в другой;
`Remove redundant assemblies` — удаление сборок, вложенных в другие.
Выход: `_raw.out` (сборки со счётчиками по позициям), `_final.out`, `_assembled_reads.fa`.

**Стадия 3. Аннотация** (`annotator`). Консенсус каждой сборки выравнивается на V/D/J/C → гены, координаты
CDR1/2/3 (`_annot.fa`). Затем все риды заново выравниваются на сборки, и в каждой сборке перечисляются
варианты CDR3, поддержанные ридами, с числом ридов (`_cdr3.out`); с `--outputReadAssignment` — какой рид в
какую сборку попал (`_assign.out`).

**Стадия 4. Отчёты.** `trust-simplerep.pl` → `_report.tsv` (клонотипы: `count`, `frequency`, CDR3 nt/aa,
V/D/J/C); `trust-airr.pl` → `_airr.tsv` (строка = сборка × вариант CDR3: `sequence` — консенсус сборки с этим
CDR3, `v_call…c_call`, `junction`, CIGAR, `v_identity`, `consensus_count`) и `_airr_align.tsv`.

```
сборка (один консенсус V)   [ V-консенсус ][CDR3 вар.1][ J ]  → строка AIRR 1
                            [ V-консенсус ][CDR3 вар.2][ J ]  → строка AIRR 2
```

Отсюда мозаики: варианты V родственников слились в один консенсус, а наружу размножен только CDR3.

**Воронка на наших данных**

| | ридов | сборок (raw) | после удаления вложенных | сборок с CDR3 | строк AIRR = контигов |
|---|---|---|---|---|---|
| мышь ERR346600 | 6 500 000 | 6 887 | 6 437 | 4 540 | 61 876 |
| человек | 27 260 000 | 109 553 | 84 890 | 64 761 | 291 488 |

### rnaSPAdes

- Репозиторий: https://github.com/ablab/spades
- Документация: https://ablab.github.io/spades/rna.html
- Статья: Bushmanova E. et al. *rnaSPAdes: a de novo transcriptome assembler and its application to RNA-Seq data.*
  GigaScience 8(9), giz100 (2019). doi:10.1093/gigascience/giz100
- **Для чего:** de novo сборка транскриптома из RNA-seq без референсного генома: неравномерное покрытие,
  изоформы. **Эффективен** на обычных транскриптах, где отличия между копиями — ошибки, а не биология.
  Близкие варианты (SNP, SHM) граф де Брёйна воспринимает как ошибки или ветвления.

Наш запуск: `rnaspades.py -1 R1 -2 R2 -t 20 -m 40`.

**Стадия 1. Коррекция ошибок** (BayesHammer) — в нашем запуске не выполнялась (каталога `corrected/` нет).

**Стадия 2. Граф де Брёйна** для двух k, выбранных по длине рида: k = 49, затем k = 73 (каталоги `K49`, `K73`).
Каждый рид режется на k-меры; неразветвлённые цепочки k-меров склеиваются в рёбра графа.

```
вариант A  ...CTGGG A TTCAC...      один нуклеотид различия даёт «пузырь» длиной k:
вариант B  ...CTGGG T TTCAC...           ┌─ A-ветвь ─┐
                                ...CTGGG─┤            ├─TTCAC...
                                         └─ T-ветвь ─┘
сотни родственников с разными SHM → развилки через каждые ~20 нт → граф рвётся на короткие рёбра
```

**Стадия 3. Упрощение графа:** обрезка «хвостов», удаление пузырей (ветка с низким покрытием считается ошибкой
и удаляется — так теряются редкие варианты), удаление ошибочных связей. Выход:
`assembly_graph_after_simplification.gfa`, `before_rr.fasta`.

**Стадия 4. Разрешение повторов по парам ридов и извлечение транскриптов.** Пары ридов выравниваются на граф,
по ним оценивается длина вставки, затем пути через развилки выбираются по парам → `transcripts.fasta`
(+ `hard_/soft_filtered_transcripts.fasta`). **У нас стадия пропущена:** в логе `Unable to estimate insert size`,
`None of paired reads aligned properly` — рёбра графа короче рида, рид не ложится на одно ребро, длину вставки
оценить нельзя. `transcripts.fasta` не создаётся; в бенчмарке взяты `K73/final_contigs.fasta` (рёбра графа
после упрощения). Имя контига: `NODE_1_length_356_cov_52.12` — длина и k-мерное покрытие.

### Trinity

- Репозиторий: https://github.com/trinityrnaseq/trinityrnaseq
- Документация (wiki): https://github.com/trinityrnaseq/trinityrnaseq/wiki
- Статьи: Grabherr M.G. et al. *Full-length transcriptome assembly from RNA-Seq data without a reference genome.*
  Nature Biotechnology 29, 644–652 (2011). doi:10.1038/nbt.1883;
  Haas B.J. et al. *De novo transcript sequence reconstruction from RNA-seq using the Trinity platform.*
  Nature Protocols 8, 1494–1512 (2013). doi:10.1038/nprot.2013.084
- **Для чего:** de novo транскриптом немодельных организмов, изоформы альтернативного сплайсинга.
  **Эффективен** для генов, где изоформы отличаются экзонами (длинные блоки), а не единичными заменами;
  аллельные и близкие варианты сливает.

Наш запуск: `Trinity --seqType fq --left R1 --right R2 --CPU 20 --max_memory 40G --full_cleanup --no_salmon`.

**Стадия 0. Нормализация in silico** (по умолчанию): риды прореживаются до покрытия ~200×; доли вариантов
искажаются.

**Стадия 1. Inchworm:** каталог k-меров (k = 25); берётся самый частый k-мер, жадно удлиняется самым частым
продолжением, использованные k-меры исключаются → линейные контиги.

```
частый вариант A  ──────G──────────C──────    Inchworm идёт по самым частым k-мерам → контиг A
редкий вариант B  ──────T──────────A──────    общие с A k-меры уже израсходованы →
                                               от B остаются обрывки по 25–50 нт
```

**Стадия 2. Chrysalis:** контиги Inchworm, разделяющие (k−1)-меры и связанные ридами, объединяются в
компоненты; для каждой строится граф де Брёйна; риды распределяются по компонентам.

**Стадия 3. Butterfly:** по каждому графу, используя риды и пары, перечисляются правдоподобные пути →
транскрипты длиной ≥200 нт.

Выход: `Trinity.fasta` (имя `TRINITY_DN9_c0_g1_i1` = компонент / ген / изоформа), `gene_trans_map`.
Покрытия в выходе нет.

### V'DJer (только run1, для справки)

Репозиторий https://github.com/mozack/vdjer; Mose L.E. et al., *Bioinformatics* 32(24), 3729–3734 (2016),
doi:10.1093/bioinformatics/btw526. Создан для сборки BCR из RNA-seq. На наших данных — 0 контигов: его фильтр
покрытия требует ридов, целиком лежащих внутри окна V…J, что при фрагментах 250 нт не выполняется. Закрыт.

## 9. Ветка с хвостами праймеров ПЦР1

Ветка `…tails_c1400…`: та же симуляция, но праймеры ПЦР1 несут хвосты (адаптер TruSeq Universal 58 нт с 5′-конца,
RC индексного адаптера с NNNN 68 нт с 3′-конца, как в реальном продукте ПЦР1) и разброс эффективности ПЦР1
откалиброван по UMI человека (концентрация Beta c = 1400).

| TRUST4 | мышь: точно (из 33 979) | мышь: partial | человек: точно (из 48 100) | человек: partial |
|---|---|---|---|---|
| база | 18 631 (54.8%) | 1 961 (5.8%) | 15 305 (31.8%) | 20 192 (42.0%) |
| хвосты | 6 198 (18.2%) | 16 453 (48.4%) | 6 984 (14.5%) | 30 529 (63.5%) |

CDR3 TRUST4 находит почти так же: мышь 25 445 / 25 463 (99.9%), человек 42 741 / 43 051 (99.3%).
rnaSPAdes у человека на хвостах точнее, чем на базе: 3 935 (8.2%) против 2 073 (4.3%).

**Почему хуже.** Неполные V…J на хвостах теряют 3′-сторону (CDR3 и J), и собственного контига с их CDR3-J нет:
лучшее выравнивание — на контиг родственника с той же V. Причину показало положение фрагментов с ридами
(мышь ERR346600, координаты в V…J, взвешено по парам ридов):

| | 5′-фрагменты кончаются, медиана (p10–p90) | 3′-фрагменты начинаются, медиана (p10–p90) | пары, фрагмент которых содержит и V за 150 нт до CDR3, и CDR3 |
|---|---|---|---|
| база | 246 (196–297) | 139 (87–190) | 631 841 / 2 565 396 (24.6%) |
| хвосты | 188 (138–240) | 207 (155–258) | 49 959 / 2 565 356 (1.9%) |

Хвосты удлиняют молекулу на 126 нт. При одном случайном разрезе каждый фрагмент начинается у конца молекулы, а отбор
250 ± 40 нт оставляет фрагменты примерно одной длины, поэтому фрагменты от двух концов почти перестают перекрываться
внутри V…J. Тело V и CDR3 редко оказываются в одном фрагменте, и сборщику не из чего узнать, какой вариант V
(с какими SHM) идёт с какой CDR3-J.

Проверено, что дело не в последовательности хвостов в ридах и не в глубине:
- обрезка хвостов в ридах (cutadapt; хвост найден у 57% R1 и 56% R2) перед TRUST4 даёт на ERR346600 точно
  421 / 1 766 (23.8%) против 400 (22.7%) без обрезки и 769 (43.5%) на базе;
- число пар ридов на V…J в двух ветках одинаково (медиана 111 и 112, у 1% самых частых V…J — 79% ридов), а точная
  сборка падает в каждой группе глубины, у V…J с ≥1 000 парами — 387 / 490 (79.0%) против 247 / 488 (50.6%).

## Итог

- TRUST4 — единственный рабочий сборщик: точно 18 631 / 33 979 (54.8%) V…J мыши и 15 305 / 48 100 (31.8%)
  человека; CDR3 — у 99.95% и 99.3% клонотипов.
- Ошибки TRUST4 — не химеры, а шум одноридовых контигов (порог ≥3 рида убирает 71% контигов за 0.3–0.5 п.п.
  полноты) и смешение мутаций родственников.
- rnaSPAdes (1.5% / 4.3%) и Trinity (0.1% / 0.3%) не подходят: их правильные контиги — куски без целой V…J.
- С хвостами праймеров ПЦР1 точная сборка TRUST4 падает до 18.2% (мышь) и 14.5% (человек): при отборе 250 ± 40 нт
  фрагменты удлинённой молекулы почти не связывают тело V с CDR3. Параметры фрагментации, от которых это зависит, —
  окно отбора по размеру и длина рида.
