по папке своего датасета:

```

```

## Публикационная раскладка мыши

Локальная рабочая копия сохраняет обе mouse-ветки раздельно. В публикуемой версии
репозитория содержимое проверенной `ERP003950_fastp_q30_u40` представлено под
каноническим путём `results/ERP003950`; legacy-ветка остаётся только локально.
Это отображение меняет путь публикации, но не вычислительную логику notebooks.

Правило публикации: все mouse-ноутбуки (подготовка, симуляция, сборка, оценка) лежат в
`results/ERP003950/notebooks/` без суффикса `_fastp_q30_u40`; в именах файлов и путях внутри
публикуемых файлов `ERP003950_fastp_q30_u40` заменяется на `ERP003950`. Папка
`results/ERP003950_fastp_q30_u40/` исключена из git (`.gitignore`). На OneQ ноутбуки лежат так же:
`<notebooks>/ERP003950/`.

## Схема тримминга

Ноутбуки адаптерного триминга с текущей политикой имеют в имени явный суффикс
`*_fastp_q30_u40.ipynb`:

- `cutadapt` снимает только технические префиксы и адаптеры;
- `fastp` фильтрует целые пары: `-q 30 -u 40 -l 250`
  `--disable_adapter_trimming --disable_trim_poly_g`;
- обрезки концов по качеству нет (никаких `--quality-cutoff` у cutadapt и
  никаких `--cut_*` у fastp).

Если для конкретного run адаптер не подтверждён, cutadapt пропускается и
выполняется только fastp-фильтрация (пример: `SRR19646180` у лошади).

Последовательности праймеров заданы прямо в праймерных ноутбуках
(dict `PRIMERS`), FASTA создаётся на время запуска внутри staging-каталога.
Внешние файлы праймеров больше не требуются.

## Атомарная замена стадий

Все стадии (`trimmed`, `pr_trimmed`) пишутся сначала в скрытый staging-каталог
рядом с целевой папкой, проверяются на полноту и только затем заменяют
предыдущий результат. Старая стадия сохраняется как `.<имя>.previous` и
удаляется только после успешной замены.
