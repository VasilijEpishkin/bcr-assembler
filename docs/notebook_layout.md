# Структура ноутбуков и результатов

Ноутбуки лежат в папке своего датасета, результаты стадий — рядом:

```
results/<DATASET>/notebooks/*.ipynb
results/<DATASET>/<стадия>/fastqc/, multiqc/      отчёты QC стадии (raw, trimmed, pr_trimmed, merged, post_annotation_filtered)
results/<DATASET>/<стадия>/fastp_reports/         отчёты fastp
results/<DATASET>/<стадия>/*_summary.json, merged/assembly_qc.tsv   сводки стадий
results/<DATASET>/read_geometry/                  распределения длин ридов по стадиям
```

## Раскладка

| Папка | Что там |
|---|---|
| `results/PRJEB40348/notebooks` | человек: адаптерный триминг + праймерный триминг |
| `results/PRJNA848968/notebooks` | лошадь: адаптерный триминг + праймерный триминг |
| `results/PRJNA900592/notebooks` | овца: адаптерный триминг, праймерный триминг, pRESTO merge, сравнение аннотаторов |
| `results/PRJEB30386/notebooks` | человек IGH/IGK/IGL: подготовка, симуляция, валидация, сборка, оценка |
| `results/ERP003950/notebooks` | мышь, тяжёлая цепь IgG: подготовка (fastp), симуляция, валидация, сборка, оценка |
| `results/PRJNA1226555/notebooks` | мышь, лёгкие цепи IGK/IGL: триминг, сборка пар ридов, сравнение веток предобработки и выбор ветки |

Общая папка `notebooks/`: `qc.ipynb` — FastQC и MultiQC любой стадии любого датасета,
`simulation_report.ipynb` — отчёт по стадиям симуляции.

## Публикация выбранной ветки предобработки

В репозитории и на OneQ лежит только выбранная ветка предобработки, под каноническим именем датасета:
мышь IGH — ветка `fastp_q30_u40` как `results/ERP003950`, лёгкие цепи — ветка `fastp_q30_u40_min250` как
`results/PRJNA1226555`. В именах файлов и путях внутри публикуемых файлов имя ветки заменяется каноническим.
Рабочие копии веток (`results/ERP003950_fastp_q30_u40/`, `results/PRJNA1226555/branches/`) в git не входят.

## Схема тримминга

Ноутбуки адаптерного триминга (`adapter_trim_<вид>.ipynb`) работают по текущей политике `fastp_q30_u40`;
суффикс ветки в имя файла не входит:

- `cutadapt` снимает только технические префиксы и адаптеры;
- `fastp` фильтрует целые пары: `-q 30 -u 40 -l 250`
  `--disable_adapter_trimming --disable_trim_poly_g`;
- обрезки концов по качеству нет (никаких `--quality-cutoff` у cutadapt и
  никаких `--cut_*` у fastp).

Если для конкретного run адаптер не подтверждён, cutadapt пропускается и
выполняется только fastp-фильтрация (пример: `SRR19646180` у лошади).

Последовательности праймеров заданы прямо в праймерных ноутбуках
(dict `PRIMERS`), FASTA создаётся на время запуска внутри staging-каталога.

## Атомарная замена стадий

Все стадии (`trimmed`, `pr_trimmed`) пишутся сначала в скрытый staging-каталог
рядом с целевой папкой, проверяются на полноту и только затем заменяют
предыдущий результат. Старая стадия сохраняется как `.<имя>.previous` и
удаляется только после успешной замены.

## Схема имён ноутбуков

`<стадия>_<вид или цепь>[_<уточнение данных>].ipynb`, без суффиксов веток предобработки:
`adapter_trim_mouse`, `presto_light_mouse`, `simulate_{human,mouse}_post_annotation_filtered_insilicoseq_150bp_novaseq[_<вариант симуляции>]`,
`assemble_<сборщик>_<вид>`, `benchmark_assemblers_<вид>`.
