# Глоссарий: сущности проекта и их связи

## 1. Путь молекулы: от клетки до контига

```
КЛЕТКА / мРНК BCR
  5'─[лидер]─[V ............ ]─[D]─[J]─[C ......]─3'
                 FR1 CDR1 FR2 CDR2 FR3 │CDR3│ FR4
                                      └─ стык V(D)J: самый разнообразный участок
                 ▲ соматические гипермутации (SHM) — замены, отличающие родственные клоны

ПЦР1 (таргетная) — праймеры на FR1 (мышь) / лидер (человек) и на C
  ШАБЛОН = физический ампликон ПЦР1 (~430–530 нт)
  [адаптер|NNNN|FR1-праймер]══V══│CDR3│══J══[C-праймер|NNNN|адаптер]
                     └──────── ЭТАЛОН: участок V…J (vj_start…vj_end) ────────┘

ПОРЦИЯ (in…ng): сколько нг продукта ПЦР1 идёт на фрагментацию → тысячи КОПИЙ каждой МОЛЕКУЛЫ

ФРАГМЕНТАЦИЯ (random_cut: один случайный разрыв на копию)
  копия 1:  ══════════════╳════════════════════════
  копия 2:  ═════════════════════════╳═════════════
  ФРАГМЕНТЫ:  ━━━━━━━━━━━━━━   ━━━━━━━━━━━━━━━━━━━━━━━━━   ...
  ОТБОР ПО ДЛИНЕ (ss200-350h25 — диапазон 200–350 нт, вне него вероятность вдвое меньше на каждые 25 нт;
                  фрагменты < 152 нт не читаются)

ПЦР2 → секвенирование PE150
  фрагмент  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  (250–350 нт)
  ПАРА:     [R1 >>>>>>>>>>>>>>]          [<<<<<<<<<<<< R2]
            └─ 150 нт ─┘   не прочитанный промежуток   └─ 150 нт ─┘
            (если фрагмент < 300 нт, R1 и R2 перекрываются)

СБОРЩИК (TRUST4 / MiXCR …) → КОНТИГИ → сравнение с ЭТАЛОНАМИ
```

## 2. Сущности

| Термин | Что это | Где лежит / как связано |
|---|---|---|
| **Шаблон** (template) | Физический ампликон ПЦР1 с праймерами. Из него симулируются риды. | `00_primary_truth/<sample>_templates.fasta` |
| **Эталон** (truth, «истина») | Участок V…J шаблона. Одинаковые V…J объединены в один эталон; у мыши сравнение идёт без первых 20 нт (там праймер FR1). Это то, с чем сравниваются контиги. | строится оценкой из шаблонов; в ERR346600 их 1766 |
| **Проверенный** (verified) | Эталон, чья последовательность подтверждена в исходных данных (мышь: после схлопывания ошибок `ec1x3`; человек: консенсус UMI ≥ 2 ридов). Только они входят в долю восстановленных. | `template_qc.tsv`, колонка verified |
| **Молекула / копия** | Одна стартовая молекула шаблона; после ПЦР1 — тысячи её копий. | модель симуляции |
| **Фрагмент** | Кусок копии после разрыва. | `02_fragmentation` |
| **Отбор по длине** | Вероятность, что фрагмент длины L попадёт в ПЦР2: 1 внутри диапазона, вне него `2^(−d/h)`, d — расстояние до диапазона, h — полуспад (нт). | `BCR_SIZE_SELECTION_RANGE`, `BCR_SIZE_SELECTION_HALVING_NT` |
| **Рид, пара, мейт** | Прочитанные концы фрагмента: R1 и R2 (мейты) составляют пару. | `06_fastq_pe150/<sample>_R1/R2.fastq.gz` |
| **Вставка** (insert) | Длина фрагмента между концами пары. | оценивается по перекрытию R1/R2 |
| **UMI** | Случайная метка молекулы (только у человека, PRJEB30386); риды одной UMI → консенсус. | ветки `umicons` |
| **Ветка** | Один вариант симуляции с набором параметров (имя кодирует параметры, см. `simulation_library_explained.md` §3). | `results/<датасет>/simulated/<ветка>/` |
| **Образец** | Один прогон секвенирования (мышь: ERR346596…601; человек: один объединённый). | внутри ветки |

## 3. Сущности сборки

| Термин | Что это |
|---|---|
| **Контиг** | Одна выходная последовательность сборщика. |
| **Сборка TRUST4** (assembly) | Внутренний кластер TRUST4: набор ридов + консенсус. Выдаёт контиги (по одному на вариант CDR3, V — общий консенсус → мозаики). |
| **Мозаика** | Контиг, склеенный из кусков разных клонов (ложная фаза). Главный дефект TRUST4. |

## 4. Метрики оценки

| Метрика | Смысл |
|---|---|
| **Точно целиком** (exact_full) | Есть контиг, содержащий весь V…J эталона без единой ошибки. |
| **1 отличие** (one_diff) | Лучший контиг покрывает весь V…J с одним отличием. |
| **п.п.** (процентный пункт) | Разница двух долей в процентах: 27,35% − 22,65% = 4,70 п.п. Это не относительный прирост: относительно исходных 22,65% он ≈ 20,8%. |
| **Поддержка контига** | Сколько наблюдений за контигом. У TRUST4 — `consensus_count` приписанных ридов, у SPAdes — среднее k-мерное покрытие `cov`; величины разные, напрямую не сравниваются. |
| **Порог** | Число, по которому принимают решение: оставить контиги с поддержкой ≥ 3 ридов, считать выравнивание близким при покрытии ≥ 95% и идентичности ≥ 98%. Меняет компромисс между полнотой и шумом. |
| **Потолок** (идентифицируемость) | Доля эталонов, которые в принципе однозначно восстановимы по этим ридам. Классы: **восстановимые** (linkage — все соседние различия связаны парами), **фаза не определена** (ambiguous — есть разрыв без связующих пар), **не покрыты** (uncovered). |

## 6. Инструменты

| Инструмент | Роль |
|---|---|
| **TRUST4** | Сборщик BCR/TCR (k-меры, жадная сборка). У нас — лучший из готовых сборщиков. Эталоном (истиной) не является. |
| **MiXCR** | Сборщик/аннотатор (выравнивание на V/D/J, клонотипы). |
| **rnaSPAdes, Trinity, GATHeR** | Прочие сборщики в сравнении. |
| **InSilicoSeq (iss)** | Генерирует риды с ошибками секвенирования из фрагментов. |
| **IgBLAST** | Аннотация V/D/J, CDR3 при построении шаблонов. |

## 7. Таблицы оценок (`docs/evaluation_history`)

- `full_runs_summary.tsv`: `run/date/dataset/branch/scoring/tool` — происхождение результата; `group_by/group` — разрез
  (образец, цепь, копии и т. п.); `templates` — знаменатель полноты; пять `*_frac` — доли классов полноты,
  `cdr3_in_contig_frac` — доля найденных CDR3.
- `full_runs_precision.tsv`: те же поля происхождения, `sample`, `contigs` — знаменатель точности; `exact_full_frac`,
  `near_full_frac`, `correct_partial_frac`, `incorrect_frac`, `unmapped_frac`, `unverified_match_frac` — классы точности;
  `structure_*_frac` — девять классов структуры.
- `full_runs_structure.tsv`: `support_type` — тип поддержки (риды TRUST4 либо покрытие SPAdes); `support_bin` — диапазон
  поддержки; `contigs` и девять классов структуры — числа внутри диапазона; `table=support_thresholds`, `min_support`,
  `contigs_kept`, `verified_exact_recall` — результат применения порога.
- `pilots.tsv`: `pilot` — название пилота; `condition` — режим; `metric` — величина; `value` — значение; `source` —
  исходная сводка. Доли и абсолютные числа различаются по `metric`: проверять единицы и знаменатель.
