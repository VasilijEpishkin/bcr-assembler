# Оценки сборщиков: файлы и легенда метрик

Локальная копия лёгких результатов с OneQ: сводки бенчмарков, построчные таблицы,
пилоты, карта идентифицируемости, перебор параметров библиотеки. Тяжёлые файлы
(контиги, BAM, FASTQ, рабочие каталоги `work/`) остаются на OneQ.

Формулы ниже взяты из кода, который считал таблицы:

- `benchmark_assemblers_{mouse,human}.ipynb` — recall, precision, структура контигов;
- `simulate_*` — восстановимость;
- `scripts/identifiability_ceiling.py`, `scripts/trust4_vs_ceiling.py`,
  `scripts/sweep_identifiability.py` — потолок.

## Где что лежит

| Путь | Что внутри |
|---|---|
| `evaluation_history/` | Сводки всех полных прогонов и пилотов в одном формате (копия `/data/user/epishkin/results/evaluation_history/`). Свой README с описанием прогонов и пилотов |
| `<датасет>/<ветка>/qc/` | Отчёт симуляции `simulation_report.md` (формулы в колонке «Откуда»), сводки восстановимости |
| `<датасет>/<ветка>/benchmark*/` | Сводки бенчмарка (`assemblers_*.tsv`) и построчные таблицы `<tool>/<sample>/per_template.tsv`, `per_contig.tsv` |
| `<датасет>/<ветка>/identifiability_map_20261001/` | Потолок восстановимости по образцам, построчно (`*_identifiability.tsv`) и сводно; сравнение с TRUST4 (`trust4_vs_ceiling.tsv`) |
| `evaluation_history/identifiability_sweep.tsv` | Потолок при других параметрах библиотеки (раздел 8) |
| `<датасет>/benchmark_v2/` | Сводки первого прогона (`run1_v2`; его ветки удалены) |

Ветки симуляции: `random_cut_…in5ng…` — базовая; `…tails_c1400…` — с хвостами
праймеров ПЦР1 (адаптеры, NNNN/UMI) и откалиброванным разбросом эффективности ПЦР1.

## 1. Эталон

| Термин | Что значит | Как считается |
|---|---|---|
| шаблон (template) | Одна исходная последовательность до ПЦР1 | Мышь: уникальный рид после схлопывания ошибок (вариант с 1 заменой поглощается соседом, который встречается ≥3× чаще). Человек: консенсус UMI |
| `verified` | Шаблон входит в знаменатель оценки | Мышь: ≥2 рида после схлопывания. Человек: консенсус UMI по ≥2 ридам без ничьих. Непроверенные тоже симулируются и дают риды, но оцениваются отдельной строкой `UNVERIFIED` |
| уникальная V..J (`unique_vj_trim<N>`) | Единица оценки в текущей схеме | Участок `[vj_start + N, vj_end)` шаблона, N = 20 у мыши (зона FR1-праймера), 0 у человека. Шаблоны с одинаковым участком объединяются; `members` — сколько объединено; проверена, если проверен хоть один |
| `copies` | Группа по числу исходных копий | `1`, `2-4`, `5+` — сумма копий объединённых шаблонов |

## 2. Восстановимость (`reconstructability`) — что физически есть в ридах

Считается при симуляции по истинным координатам фрагментов. R1 = `[start, start+150)`,
R2 = `[end−150, end)`; связь между позициями b−1 и b:

| Класс | Что значит |
|---|---|
| `no_reads` | V..J шаблона не попал в FASTQ |
| `partial_read_coverage` | Часть V..J не прочитана ни одним ридом |
| `full_coverage_unlinked` | Всё прочитано, но есть точка, которую не пересекает ни один фрагмент |
| `full_coverage_mate_linked_only` | Каждая точка пересечена фрагментом, но хотя бы одна — только промежутком между R1 и R2 |
| `full_coverage_read_overlap` | Каждая точка лежит внутри одного рида, ≥31 нт с каждой стороны: собирается обычным перекрытием |

Этот класс проверяет связность одного шаблона, без учёта соседей. Различимость от
близких клонов проверяет потолок (раздел 7).

## 3. Recall — сколько эталона собрано (по эталонным V..J)

Каждая проверенная V..J выравнивается на контиги (`minimap2 -c -x sr`), берётся
лучшее выравнивание по (совпадения − правки, длина выравнивания).
`cov = (qe − qs) / qlen` — доля V..J в выравнивании; `ident = match / block`;
`NM` — число замен и индэлов.

| Колонка | Класс | Условие |
|---|---|---|
| `exact_full_frac` | собрана точно | `cov = 1` и `NM = 0`: вся V..J без единого отличия внутри одного контига |
| `one_diff_full_frac` | одно отличие | `cov = 1` и `NM = 1` |
| `near_full_frac` | почти целиком | `cov ≥ 0.95` и `ident ≥ 0.98`. Мягкий порог: путает клональных родственников |
| `partial_frac` | частично | Остальное с выравниванием |
| `missing_frac` | не найдена | Выравнивания нет |

Каждая `*_frac` = число V..J в классе / `templates` (размер группы). Сумма пяти долей = 1.

`assemblers_summary.tsv`: `tool`; `group_by` — разрез (`reconstructability`,
`copies`, `locus`, `cdr3_clonotypes`); `group` — значение (`ALL` — все проверенные,
`UNVERIFIED` — все непроверенные отдельно); `templates` — размер группы.

## 4. CDR3

| Колонка | Как считается |
|---|---|
| `cdr3_in_contig_frac` | Клонотип = (локус, junction) среди проверенных шаблонов. Найден, если junction целиком встречается в контиге, на который выровнен любой шаблон этого клонотипа. Доля = найденные / все клонотипы группы |
| `group = …:sequenced` | Клонотипы, у которых хотя бы один шаблон получил риды |
| `group = …:no_reads_control` | Отрицательный контроль: ни один шаблон не прочитан. Ненулевая доля значит, что CDR3 совпал случайно (у родственника) |

## 5. Precision — насколько верны контиги (`assemblers_precision.tsv`, по контигам)

Каждый контиг выравнивается на эталонные V..J, лучший хит с предпочтением
проверенных. `tcov = (te − ts) / tlen` — доля эталона в выравнивании.

| Колонка | Условие |
|---|---|
| `exact_full_frac` | `tcov = 1` и `NM = 0`: контиг содержит эталонную V..J целиком |
| `near_full_frac` | `ident ≥ 0.98` и `tcov ≥ 0.95` |
| `correct_partial_frac` | `ident ≥ 0.98` и выравнивание ≥100 нт |
| `unverified_match_frac` | Один из трёх классов выше, но лучший эталон непроверенный |
| `incorrect_frac` | Выравнивание есть, но хуже порогов |
| `unmapped_frac` | Выравнивания нет |

Доли = контиги в классе / `contigs` (число контигов образца).

## 6. Структура контигов (`structure_*`, `assemblers_structure_by_support.tsv`)

Выравнивание контига на все эталоны с позициями отличий (`minimap2 --cs`).
Классы проверяются по порядку, первый подошедший побеждает:

| Класс | Условие |
|---|---|
| `exact_verified` / `exact_unverified` | Контиг содержит какую-то эталонную V..J целиком без отличий (проверенную / только непроверенную) |
| `chimera` | 5'- и 3'-части контига (по 60% длины, контиги ≥200 нт) точно совпадают с разными эталонами |
| `mosaic` | Каждое отличие от лучшего эталона (ident ≥ 0.98) есть у другого проверенного эталона в этой позиции: перемешаны мутации родственников |
| `unverified_variant` | Отличия объясняются только непроверенными эталонами (среди них могут быть ошибки исходных данных) |
| `novel_error` | Есть отличие, которого нет ни у одного эталона: ошибка сборки |
| `other` | Нет выравнивания с ident ≥ 0.98 |
| `unmapped` | Нет выравнивания вовсе |

**Поддержка контига** (`support_type`): TRUST4 — `reads`, число ридов
(`consensus_count` из AIRR); rnaSPAdes — `kmer_coverage`, `cov` из имени контига;
Trinity — нет.

- `assemblers_structure_by_support.tsv`: доли классов структуры среди контигов с
  поддержкой в диапазоне `support_bin` (1, 2–4, 5–9, 10–49, 50+).
- `assemblers_support_thresholds.tsv`: что будет, если выбросить контиги с поддержкой
  ниже `min_support`. `contigs_kept` — сколько осталось; `verified_exact_recall` —
  доля проверенных V..J, которые всё ещё собраны точно (их лучший контиг прошёл
  порог); доли структуры — среди оставшихся контигов.

## 7. Потолок восстановимости (`identifiability_map_20261001/`)

Вопрос: мог бы безошибочный сборщик однозначно восстановить эту V..J по тому, что
есть в ридах? Единица — проверенная уникальная V..J (раздел 1), знаменатель тот же,
что у recall.

**Соседи.** Другие уникальные V..J того же локуса (включая непроверенные — их риды
тоже есть в данных) с расхождением ≤10%. Сравниваются в двух выравниваниях:
от начала (сторона V) и от конца (сторона J). Позиции за концом более короткой
последовательности считаются различиями.

**Связь двух позиций a и b.** Число пар ридов самой V..J, видящих обе позиции:
обе в одном риде или одна в R1, другая в R2 той же пары.

| Колонка | Класс / значение | Условие |
|---|---|---|
| `strict_class_k<k>` | `uncovered` | Какая-то позиция V..J покрыта < k парами ридов |
| | `linkage` | Для каждого соседа каждую пару соседних различающихся позиций (a, b) связывают ≥ k пар. Мозаики исключены данными |
| | `ambiguous` | С каким-то соседом есть несвязанная пара (a, b): решения «A…G + T…C» и «A…C + T…G» объясняют данные одинаково |
| `heuristic_class_k<k>` | `frequency` | Как `ambiguous`, но со всеми такими соседями число пар ридов различается ≥2×: фазу можно угадать по частоте. Эвристика, в строгий потолок не входит |
| `ceiling_fraction` | потолок | `linkage` / `truths` |
| `uncovered_positions_k<k>` | | Сколько позиций покрыто < k парами |
| `close_neighbours_k<k>` | | Число соседей с расхождением ≤10% |
| `unbridged_neighbours_k<k>` | | Сколько из них дают хотя бы одну несвязанную пару |
| `worst_gap_k<k>` | | Самая длинная несвязанная пара `a-b` в координатах V..J |
| `read_pairs` | | Сумма пар ридов всех фрагментов этой V..J |

`k = 1` — достаточно одной пары ридов; `k = 2` — нужны две, мягкая защита от
случайности. k считает пары ридов, а не независимые молекулы.

**Ограничения.** Используется истинное происхождение фрагментов; в симуляции нет
ошибок ПЦР и химер; тест попарный — необходимое, но не достаточное условие
однозначности смеси из трёх и более клонов. Поэтому `linkage` — верхняя граница.

`trust4_vs_ceiling.tsv` — та же таблица плюс `trust4_exact`: V..J целиком входит
в один контиг TRUST4 на любой цепи (то же, что `exact_full`).

## 8. Перебор параметров библиотеки (`evaluation_history/identifiability_sweep.tsv`)

Тот же эталон и те же фрагменты, меняется только геометрия:

- **длина фрагмента** перетягивается из N(`frag_mean`, `frag_sd`) и обрезается до
  длины шаблона (длиннее = неразрезанная молекула). Фрагмент остаётся привязанным к
  своему концу шаблона, как при одиночном разрезе;
- **длина ридов** — `read_len`;
- **глубина** — `depth`, множитель числа разных фрагментов на молекулу. Каждая копия
  получает свою длину; число пар ридов на фрагмент (дубликаты ПЦР2) сохраняется.

| Колонка | Что значит |
|---|---|
| `branch`, `sample` | Ветка симуляции и образец |
| `scenario` | Имя сценария: `frag<mean>_pe<read_len>[_depth<d>]` |
| `k`, `truths`, `linkage`, `ambiguous`, `uncovered`, `ceiling_fraction` | Как в разделе 7 |

Сценарий `frag250_pe150` на базовой ветке воспроизводит реальную симуляцию
(отбор 250 ± 40 нт, 2×150) и служит проверкой: его потолок должен совпасть с картой
идентифицируемости. Модель с несколькими разрезами (ультразвук) не перебирается.
